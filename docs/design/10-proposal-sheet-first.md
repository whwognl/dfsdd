## 0. 한눈에 보기

**관점**: 사용자는 엑셀 시트로 일하던 사람입니다. 앱은 "시트가 곧 작업대"여야 하고, 나머지 기능(복사·발주완료·CS·블랙리스트·송장·메모)은 전부 **시트 행 옆에 붙어 있어야** 합니다. 대시보드·CS는 시트에서 한 번 눌러 가고, 한 번 눌러 돌아옵니다.

**전제**: 구앱을 갈아엎지 않습니다. 이미 작업 트리에 들어온 것(36열 어댑터·36열 내보내기·블랙리스트·복사 툴바·CS 확장)을 **기준선(Phase A)** 으로 삼고, 그 위에 얹는 개선만 다룹니다. 탭/패널/함수/DOM id는 하나도 지우지 않습니다(`init()`의 널 참조로 앱이 죽는 구조이므로).

## 0.1 지금 작업 트리에 있는 것 (Phase A 기준선) — 전부 [확인]

Phase B 설계는 아래를 "이미 있다"고 가정합니다. 없는 것을 있다고 착각하면 계획이 어긋나므로 먼저 적습니다.

- **소스 36열 어댑터**: `FIELDS`에 36열 별칭 + 신규 필드 23개(`collectedAt … uniqueNo`), `SOURCE_HEADERS` 상수(28열 전각공백 포함), `autoMap`은 헤더 소비·거부어 방식, `keyOf`는 `uniqueNo` 우선(`legacyKeyOf` 폴백), `buildOrders`가 주문여부 O→`purchased`, 송장+배송사→`invoiced`, X→`csType="취소요청"`. `mergeOrders`로 "기존 주문에 합치기"(`#opt-merge`).
- **36열 내보내기**: `sourceRow`/`exportSource(xlsx|xls|csv)`, "송장 있는 건만" 스위치(`#exp-src-only-invoiced`), 출고중지·반품·취소·품절은 송장 칸 비움 + 한줄메모에 `[유형]` 접두. 상단 `#btn-quick-invoice`는 올린 파일이 `.xls`면 `.xls`로, 아니면 `.xlsx`로 `exportSource`를 부름. 쿠팡 39열 `exportInvoice`는 보조.
- **엑셀 엔진**: SheetJS 없이 `xlsx-lite.js + biff.js + xlsx-compat.js`. `.xls` 읽기·쓰기 가능(05 보고서, xlrd 기준 검증).
- **마진식**: `computeMargin`이 워크북식 `((판매가+배송비)×(1−율×1.1) − 구매금액(총액 우선) − 에누리 − CS차감) ÷ 1.1`. 단 `renderMarginCalc`(마진계산기 탭)는 아직 옛 식(`판매가×(1−율) − 소싱가`)이라 두 화면 숫자가 다릅니다.
- **블랙리스트**: `blacklist.js`(이름 정확일치·마스킹 와일드카드·주소 숫자토큰 전부 일치·연락처 뒤 8자리·행정구역만 겹치면 제외), `computeRisk`가 `o.risk={level,reasons}`, 시트 `위험` 열 배지, `row-danger`/`row-warn` 행 색, 주문관리 상단 `risk-banner`, 파일 올린 직후 `showRiskModal`, 블랙리스트 탭(직접 추가·붙여넣기·재검사·일치 목록·주문으로), 메모 모달의 [블랙리스트 등록], 설정의 워크북 가져오기에서 `블랙리스트` 시트 명단 흡수. 탭 카운트 배지.
- **복사 툴바** `#copy-bar`: 행 번호/계산 셀 클릭으로 행 선택 → [이름][전화·내번호][우편번호][기본주소][상세주소][배송메시지][전체] + 내 번호 형식 select + 순차 모드(P1/P2/P3, 구매처별 기억) + [CS ▾] + [입력준비 ↗](구매링크 새 탭) + [구매완료 표시](결제일시·주문여부 기록). 전화는 `getAutofillPhone()` 단일 출처, 비어 있으면 차단.
- **CS 확장**(커밋 전, 작업 트리): `CS_TYPES` 11종, `o.cs{openedAt, reason, channel, waitingOn, steps, nextAction, nextActionAt, deadline, pickup, supplierClaim, coupangRequest, ledger}`, `CS_STEPS` 유형별 체크리스트, `CS_LEDGER_KINDS` 부호 있는 장부(`csCost`는 장부 합계에서 파생, `csSync`), 멘트 템플릿 7종, CS 탭 3단(오늘 할 일/기다리는 중/종결) + 아코디언 상세 + 타임라인 + [주문으로](`gotoOrder`) + 회수용 고객번호 복사(별도 함수 `csCopy`).
- **시트 엔진**: 열 드래그 순서·너비, 행 높이, 사용자 열, 블록 붙여넣기, 삭제 복구, `SHEET_LAYOUT_VERSION=27`. 행 선택 `sel-row`. 검색 hay에 `uniqueNo·orderId·vendor·account·note·invoiceNumber` 포함.
- **테스트 도구**: `tools/smoke.js`(playwright, 탭 전부 렌더·업로드·복사 툴바·CS 흐름·내보내기 다운로드, 콘솔 에러 있으면 실패), `tools/verify-export.js`(36열 헤더·키 연결·T코드·우편번호 5자리), `tools/test-biff.js`, `tools/test-copy.js`, `sample/`(합성 데이터).

## 1. 상단 탭 구성

### 1.1 판단 기준
1. 하루 작업에서 **매일 여는 것**만 첫 줄에 둔다. 나머지는 한 번 더 눌러야 나와도 된다.
2. 탭을 **지우지 않는다.** `TABS`/`TAB_PANE`/`render()` 분기/`#pane-*`는 그대로. 바뀌는 건 `renderTabs()`의 그리기 방식뿐.
3. 36열 시대에 역할이 줄어든 탭은 숨기되, 데이터는 계속 쓴다(예: 라인업의 `lineupExtras`는 `buildOrders`가 링크·단가 보강에 지금도 씀 **[확인]**).

- 서브탭: `일별`=`renderDailySales`, `월별`=`renderMonthlyTable`, `카테고리`=`renderProfit`의 표 부분, `로스`=`renderLossPane`. 네 함수는 그대로 두고 대시보드가 `#overview-extra` 안에 그립니다. 기존 `#pane-daily` 등은 더보기에서도 열리게 남겨 둡니다(id 삭제 금지).
- `process-strip`은 **대시보드 탭에서만** 표시(다른 탭에서는 숨김). 주문관리에서는 위 한 줄 띠가 그 역할.
- `#summary`(5 카드)는 두 줄 띠로 대체하되 DOM id는 남김(`renderSummary`가 띠를 그리도록 변경).

### 4.3 오탐 방지 규칙 (현재 `blacklist.js` [확인] + 제안)

현재 규칙(전부 [확인]):
1. 이름: 공백·괄호·구두점 제거 후 **정확 일치**. `/`·`|`로 나뉜 복수 이름 지원. 마스킹(`김성*`)은 한 글자 와일드카드.
2. 주소: 괄호 안 참고항목 제거 → 정규화 문자열 포함 관계 또는 토큰 비교. 토큰 중 **숫자 포함 토큰(번지·동·호)은 전부 정확 일치**, 지명 토큰은 포함 관계 인정하되 3개 이상이면 n−1개 이상 일치. 숫자 토큰이 없는 등록은 지명 3개 이상 전부 일치. 등록 주소가 6자 미만이면 불일치. → "경기도 용인시 기흥구"만 겹치면 제외.
3. 연락처: 숫자만 남겨 **뒤 8자리** 일치(안심번호 앞자리 차이 무시).
4. 판정: 이름+주소 또는 연락처 → 위험 / 주소 없이 등록된 이름과 정확 일치 → 위험 / 마스킹 이름은 주소까지 맞아야 / 이름만·주소만 → 주의.

제안(추가·조정):
- **구매자명도 별도로 검사**: 지금은 `recipient || buyerName`(수령자가 있으면 구매자 무시) **[확인]**. 워크북 실측 18%가 다름(03). → 두 이름을 각각 대조, 구매자명만 맞으면 사유에 "구매자명 일치"로 표시하고 레벨은 이름만 일치와 동일.
- **이름만 등록된 항목의 레벨을 설정으로**: `rules.blacklistNameOnly = "danger"(기본) | "warn"`. 사용자의 실제 명단이 이름 1열이라 기본은 지금처럼 위험으로 두되, 흔한 이름 오탐이 잦으면 주의로 내릴 수 있게. 사용자 결정 필요(9절).
- **확인함(dismiss)**: `o.riskDismissed = true`(states에 저장). 행 색은 유지하되 배너·탭 배지·대시보드 위험 수에서 제외. 재검사(`recomputeAll`)로 사유가 바뀌면 자동 해제.
- **주소 보강 유도**: 이름만 일치한 행에 `[이 주문 주소로 보강]` → 그 등록 항목의 `address`에 주문 주소를 넣음(다음부터 이름+주소 = 위험). 명단이 이름뿐인 사용자가 자연스럽게 정밀도를 올리는 경로.
- 규칙을 느슨하게 만드는 변경은 하지 않습니다(HANDOFF 4절 경고와 동일).

### 6.4 내보내기 방어
- `sanitizeExportRows`가 36열 왕복 파일의 원문 값(예: 배송메세지가 `-`로 시작)에 `'`를 붙일 수 있음(01 §4.2). B9에서 "원본 열은 원문 그대로, 앱 입력 열(한줄메모·구매처·계정·담당자·구매처 주문번호)만 방어"로 범위 조정. 검증: `verify-export.js`에 `'` 접두 검사 추가.

## 8. 구현 순서 · 검증 (커밋 계획)

### 8.1 회귀를 막는 공통 규칙
1. **DOM id 삭제 금지**(`init()` 널 참조). 새 id는 `if (el)` 가드.
2. 렌더 함수 안 `addEventListener` 금지 — pane 단위 위임(기존 관례).
3. 시트 열을 바꾸면 `SHEET_LAYOUT_VERSION` 올리기(사용자 열 순서 초기화 고지).
4. 파일을 고치면 `index.html`의 `?v=` 올리기(현재 38).
5. 입력 중에는 부분 갱신(`refreshRowCalc` 등), 전체 `render()`는 click/change에서만.
6. 새 순수 함수는 별도 파일(`*-helpers.js`)에 두고 `window`/`module.exports` 양쪽 노출 → node 테스트.
7. 커밋마다 실행: `npm run smoke`(콘솔 에러 0, 다운로드 생성) · `node tools/verify-export.js <내보낸.xlsx> sample/소스샘플_36열.xlsx` · `npm run test:biff` · `node tools/test-copy.js`.
8. 커밋 전 `git status`로 **다른 세션의 변경이 섞이지 않았는지** 확인(지금 작업 트리에 CS 확장이 커밋 전 상태로 있음 **[확인]**).

- B2 뒤: 행을 골라도 시트가 위아래로 움직이지 않는가.
- B3 뒤: 완료 체크 한 번으로 결제일시·담당자·구매처·계정·카드가 채워지고 내보낸 파일에 O가 찍히는가.
- B4 뒤: 열을 숨겨도 엑셀에서 복사한 블록이 보이는 열 순서대로 들어가는가. 가로 스크롤해도 완료·준비·위험이 보이는가. 행 높이가 32px에서 늘지 않는가.

- B9 뒤: 구매처 화면에서 복사한 송장 표가 한 번에 붙는가.

## 9. 사용자에게 물어볼 결정 4가지

1. **이름만 등록된 블랙리스트를 위험(빨강)으로 볼지 주의(노랑)로 볼지** — 현재 명단이 이름 1열이라 기본은 빨강. 흔한 이름 오탐이 잦으면 노랑으로(4.3).
2. **더보기로 숨기는 탭 목록** — 라인업·매입처DB·마진계산기·수행일지·계정·카드·프로세스. 매일 여는 것이 있으면 주요로 올림(1.2).
3. **머리글 그룹 행**(2.2)을 켤지 — 엑셀의 병합 머리글 느낌. 싫으면 끔.
4. **송장 붙여넣기의 키** — 구매처 화면에서 복사할 때 어떤 열이 함께 오는지(주문번호? 수취인?) 실제 예시 한 줄(개인정보 가려서) 있으면 파서 우선순위를 맞춤(6.2).
