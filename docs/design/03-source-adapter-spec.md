## 0. 한눈에 보는 결론

1. **지금 구앱에 36열 파일을 올리면 매핑 화면조차 뜨지 않고 잘못 정리됩니다(확인).** `autoMap`을 36열 헤더에 실제로 돌려본 결과: 주문번호·상품명(필수 2개)만 찾으면 바로 `finalizeOrders`로 넘어가는데, 그 상태에서 `address → "배송지우편번호"`(오매핑), `recipient/option/paymentAmount/productId → 없음`이었습니다. 원인은 부분포함 규칙의 **양방향 포함**(`별칭 ⊃ 헤더`도 허용)과 **먼저 나온 열이 이김** 조합입니다. 아래 2절의 알고리즘으로 바꾸면 36열·53열 워크북·쿠팡 발주서 세 양식 모두 올바르게 붙는 것을 프로토타입으로 확인했습니다.
2. **`.xls`는 현재 읽을 수도 쓸 수도 없습니다(확인).** `index.html`이 `biff.js`를 로드하지만 저장소에 그 파일이 없습니다. `xlsx-compat.js`는 CFB(.xls) 바이트를 보면 `BiffXls`가 없다며 reject 합니다. 수집 프로그램이 준 샘플이 바로 `.xls`(BIFF8)이므로 **BIFF8 읽기(+쓰기) 엔진이 이 작업의 선결 과제**입니다. 그 전까지는 사용자가 엑셀에서 "다른 이름으로 저장 → .xlsx"를 거쳐야 합니다.
3. 매핑 결정: `phone = 수령자휴대폰번호`(비면 전화번호), `phone2 = 수령자전화번호`; `productId = 판매사이트 상품코드`(마스터·판매자상품코드는 266행 전부 비어 있음); `orderNumber = 판매사이트 주문번호` 전체 문자열; `paymentAmount = 판매가`(수량이 곱해진 **주문 합계**임을 수량 2건으로 확인); `orderId = 주문번호　앞부분`(전각 공백 포함 원문 키 그대로).
4. 새로 추가할 필드 18개: `collectedAt, site, sellerId, shipFee, masterCode, sellerCode, discount, buyerName, phone2, deliveryMsg, vendor, account, purchaseAmount, paidAt, card, point, orderedYn, note, uniqueNo`. 이 중 마진식에 들어가는 것은 `shipFee`(+), `discount`(−), `purchaseAmount`(총액, 있으면 단가×수량보다 우선).
5. **키는 `주문고유번호`로 바꿉니다.** 266행에서 판매사이트 주문번호·주문고유번호 모두 중복 0건(확인). 다만 기존 `keyOf`(주문번호¶상품ID¶옵션¶수취인)는 쿠팡 발주서와 옛 저장 상태를 위해 **2차 키로 유지**하고, 복원 시 새 키 → 옛 키 순으로 찾습니다.
6. 내보내기는 **36열 헤더를 상수로 박고(전각 공백 포함) 열마다 값 소스를 고정**합니다. 원본 열(1~13, 17~23, 34)은 `o.raw` 원문 그대로, 앱 입력 열(14~16, 24~33, 35~36)은 앱 값 우선·없으면 원문. 송장번호·주문고유번호·상품코드는 **반드시 문자열 셀**로. 시트명은 가져온 시트명(없으면 내보내는 날짜 `YYYY-MM-DD`). 기본 형식은 **가져온 파일과 같은 형식**(.xls로 왔으면 .xls), 버튼은 xlsx/xls 둘 다.
7. 붙여넣기(TSV)·CSV·구글시트 경로는 모두 `matrixToParsed → processOrderParsed → autoMap`으로 합류하므로(확인) 어댑터를 `autoMap`/`buildOrders` 한 곳에 넣으면 전 경로에 적용됩니다. 단 **CSV 파일 경로만** `xlsx-compat.textToAoa`가 숫자처럼 보이는 문자열을 float로 바꿔 우편번호 앞 0이 사라집니다(확인) — 4자리 우편번호는 5자리로 채우는 정규화가 필요합니다.

### 1.3 구앱 코드 동작

- `readWorkbook`: 첫 번째 시트만 읽고 1행을 헤더로 씀. `sheet_to_json(raw:false)`라 숫자 셀도 문자열로 넘어옴(`xlsx-compat.fmt`). 헤더는 `trim()`.
- `autoMap`: 필드별로 (1) 정확/정규화 일치 → (2) 부분포함(`헤더 ⊃ 별칭` **또는** `별칭 ⊃ 헤더`). 헤더를 소비하지 않아 같은 열이 여러 필드에 붙을 수 있음. `processOrderParsed`는 `req`(주문번호·상품명) 둘만 찾으면 매핑 화면 없이 확정.
- `buildOrders`: 행마다 새 객체를 만들고 `o.raw = 행 전체`를 보존. `state.sourcingMap[productId]`·라인업·매입처DB에서 링크/단가 보강. `states[keyOf(o)]`로 진행상태 복원. **`state.orders`를 통째로 교체**(누적 아님).
- `keyOf` = `orderNumber¶productId¶option¶recipient`. `persist`는 `states`에 `status/orderId/manager/invoiceNumber/courier/sourcingLink(s)/sourcingPrice/sourcingShipping/csType/csStatus/csCost/memoLog/customValues`를 저장(90일 보존).
- `computeMargin`: `settlement = paymentAmount×(1−rate)`, `cost = sourcingPrice×qty + sourcingShipping`, `margin = settlement − cost − csCost`, `marginRate = margin/paymentAmount`. 배송비 수입·에누리 항이 없음.
- `parseOrderDate`: 직렬값을 `new Date((serial−25569)×86400000)`로 만들어 **로컬 시간대로 읽음** → KST에서는 9시간이 더해져 15:00 이후 주문의 날짜가 하루 밀릴 수 있음(확인, xlsx는 xlsx-lite가 먼저 문자열로 바꿔 주기 때문에 .xls/CSV 직렬값에서만 발생).
- `exportInvoice`/`invoiceRow`: 쿠팡 39열 전용. `rawVal`로 원본 열을 먼저 찾고 없으면 `o.*`로 채움. `invoiceExcluded`(출고중지요청·반품접수·취소요청)는 제외.
- `exportFull`: 앱 내부 필드명으로 된 백업용 시트(36열과 무관).
- `sanitizeExportRows`: 문자열 앞이 `= + - @`이면 `'`를 붙임. 전 내보내기 경로에 적용돼 있음.
- 붙여넣기: `parsePasted → dsvToMatrix → matrixToParsed → processOrderParsed`. 구글시트: `cloudLoad → matrixToParsed → processOrderParsed`. CSV 파일: `readAsync → textToAoa`(숫자 변환 있음) → `readWorkbook`과 같은 경로.
- `COURIERS`는 이름 문자열 배열, 시트 select는 이름을 표시·저장. 코드 개념 없음.
- `index.html` 794행 `<script src="biff.js?v=38">` — **파일 없음**(저장소·archive 어디에도 없음). `xlsx-compat.readAsync`는 CFB 시그니처(`D0 CF 11 E0`)를 보면 `BiffXls` 부재로 reject, `write(bookType:"xls")`도 throw.

## 2. 36열 → 주문 필드 매핑표

`기존` = 구앱 `buildOrders`가 이미 만드는 필드. `신규` = 어댑터가 추가하는 필드. `raw` = `o.raw[원문헤더]`에 항상 보존(모든 열).

| # | 원문 헤더 | 필드 | 구분 | 가져오기 정규화 | 근거·메모 |

## 3. 값 정규화

### 3.1 날짜 (`수집일`·`주문일`·`결제일시`)

입력으로 올 수 있는 형태(확인/추정): xlsx → `YYYY-MM-DD HH:mm` 문자열(xlsx-lite 변환, 확인) · .xls → 직렬값 실수 또는 문자열(추정, 엔진 구현에 따라) · CSV/붙여넣기 → `2026-09-01 10:16`, `2026.09.01`, `9/1/2026 10:16` 등 문자열 · 직렬값이 문자열로 온 경우(`"46271.0194"`).

정규화 함수 `normDateTime(v)` → 항상 `YYYY-MM-DD HH:mm`(시:분이 없으면 `YYYY-MM-DD`) 문자열, 실패 시 원문 그대로:
1. 숫자(또는 숫자 문자열, 20000 < n < 80000) → **UTC 기준** 직렬값 변환(`xlsx-lite.serialToString` 재사용). `parseOrderDate`의 로컬 시간대 변환은 여기서 쓰지 않음(1.3의 하루 밀림 문제).
2. 문자열 → `(\d{4})[.\-/년 ]+(\d{1,2})[.\-/월 ]+(\d{1,2})` + 선택 `(\d{1,2}):(\d{2})`; `m/d/yyyy`도 허용.
3. `-`, `없음` 같은 값은 빈 문자열.

`orderDate`는 정규화한 문자열을 저장하고, 대시보드 집계(`monthKey`/`dayKey`)는 그 문자열의 앞 10자만 씁니다. **내보낼 때는 `raw` 원문이 있으면 원문을 그대로** 씁니다(문자열이면 문자열, 직렬값이면 숫자). 앱이 새로 만든 `paidAt`은 문자열 `YYYY-MM-DD HH:mm`으로 냅니다. 수집 프로그램이 문자열 날짜를 받는지는 **추정**이라 설정에 "날짜를 엑셀 날짜 셀로 내보내기"(xlsx-lite 날짜 스타일 사용) 옵션을 둡니다. 기본은 원문 그대로.

### 3.2 주문여부 ↔ 상태

| 원문 `주문여부` | 송장번호+배송사 | 가져온 `status` | 비고 |
|---|---|---|---|
| `O` | 있음 | `invoiced` | 워크북 99행 전부 이 경우(확인) |
| `O` | 없음 | `purchased` | |
| `X` | — | `pending` + `csType="취소요청"`(비어 있을 때만) + `orderedYn="X"` | 매출·마진 집계에서 제외(워크북 매출 0과 동일). `invoiceExcluded` 대상 |
| 빈칸 | 있음 | `invoiced` | 비정상이지만 사용자가 송장만 먼저 적은 경우 대비 |
| 빈칸 | 없음 | `pending` | |

이전 states가 있으면 **states의 `status`가 우선**하되, 파일이 더 진행된 상태(`invoiced` > `purchased` > `pending`)를 말하면 파일을 따릅니다(수집 프로그램에서 송장이 채워져 돌아온 경우).

내보내기 `주문여부` = `status ∈ {purchased, invoiced}` → `O`; `csType ∈ {취소요청}` 또는 `orderedYn==="X"` → `X`; 그 외 → 원문(`raw`)이 있으면 원문, 없으면 빈칸. 출고중지요청·반품접수는 이미 구매가 된 건이므로 `O`를 유지합니다(주문여부는 "구매처에 주문했나"의 답).

### 3.4 송장번호·주문고유번호·상품코드 (지수표기 방지)

`asIdString(v)`: `null/""` → `""`; 숫자 → `Number.isSafeInteger`면 `String(v)`, 아니면 `v.toLocaleString("fullwide",{useGrouping:false})`; 문자열이 `^\d+(\.\d+)?[eE]\+?\d+$` 형태면 `Number(v)`를 위와 같이 복원(12자리 정도는 안전); 끝의 `.0` 제거; 하이픈·공백 제거는 송장번호에만(`stripInvoiceNo`). 15자리 이하만 정확 복원 가능하므로 16자리 이상 지수표기 문자열은 그대로 두고 경고합니다(판매사이트 주문번호는 공백이 있어 숫자로 해석되지 않으므로 안전, 확인).

내보내기: 세 열은 항상 **문자열 셀**(xlsx-lite는 문자열을 `inlineStr`로 씀 — 확인; BIFF 쓰기 엔진도 문자열 레코드로 써야 함). CSV로 내면 엑셀에서 열 때 다시 지수표기로 보일 수 있으니 CSV는 36열 내보내기 옵션에서 뺍니다.

### 3.5 구매가(단가)·구매금액(총액)과 마진식

현재 구앱: `cost = sourcingPrice×qty + sourcingShipping`. 사용자는 실제로 총액(`구매금액`)만 씁니다(167행). 그래서:

```
sourcingCost = purchaseAmount (있으면)
             ‖ sourcingPrice×quantity + sourcingShipping (단가가 있으면)
             ‖ null
rate         = effectiveRate(feeRate)/100                   // 기존 (VAT 옵션 ×1.1)
settlement   = round((paymentAmount + shipFee) × (1 − rate))  // 배송비 수입 추가
gross        = settlement − sourcingCost − discount − csCost
margin       = vatIncluded ? round(gross / 1.1) : round(gross)  // 워크북 순마진(부가세 제외)과 동일
marginRate   = paymentAmount ? margin / paymentAmount : null
```

- `gross/1.1`은 워크북 `순마진금액 = (결제기준가 + 배송비순액 − 구매금액 − 에누리)/1.1`(HANDOFF 3절에서 실측 3행으로 검증됨)을 그대로 따른 것입니다. 지금 구앱 `margin`에는 이 `/1.1`이 없어 사용자 워크북 숫자와 **10% 차이**가 납니다. 대시보드가 사용자 숫자와 맞아야 하므로 워크북식을 권합니다. 옛 숫자를 보고 싶으면 설정의 `vatIncluded`를 끄면 됩니다(마진식 안내문 갱신 필요).
- `purchaseAmount`가 있으면 `sourcingPrice`를 무시(사용자가 총액을 수정하면 그 값이 진실). 앱에서 단가를 입력하면 `purchaseAmount`가 비어 있을 때만 `sourcingCost`가 단가×수량으로 계산되고, 내보내기 `구매금액`에는 그 계산값이 나갑니다.
- 포인트는 마진에 넣지 않습니다(워크북도 표시만).

### 3.6 그 밖의 정규화

- 우편번호: 숫자·`.0` 제거 → 4자리면 `0` 채움(5자리 우편번호 기준). 복사 포맷 `{zip}`에도 적용.
- 전화: 숫자만 남긴 뒤 `3-4-4`(11자리) / `4-4-4`(12자리, 안심번호) / 그 외 원문.
- 헤더: `trim` 뒤 U+3000·NBSP를 일반 공백으로 바꾼 **표시용 헤더**와, `o.raw` 키로 쓰는 **원문 헤더**를 둘 다 유지. 원문 헤더는 `state.sourceMeta.header`(36개 배열)에 저장해 내보내기 상수와 대조.

### 4.2 제안 알고리즘 (프로토타입으로 검증)

```

  // 0) 양식 감지: 36열 양식과 같은 위치에 같은 이름이 30개 이상이면 '위치 매핑'
  hits = count(i: nh[i] === norm(SOURCE36[i]))

  // 1) 정확(정규화) 일치 — FIELDS 순서 → 별칭 순서, 한 헤더는 한 번만 소비
  for f in FIELDS: for alias in f.aliases: 첫 미사용 헤더가 norm 일치하면 map[f.key]=그 헤더, used
  // 2) 부분포함 — partial:true 필드만, '헤더 ⊃ 별칭' 방향만, 별칭 3자 이상,
  //    deny 단어가 헤더에 있으면 건너뜀, 미사용 헤더만
  // 3) 결과 검증 — 서로 다른 필드가 같은 헤더를 갖지 않음(1·2단계가 보장)
```

핵심 규칙 세 가지: **헤더 소비(한 열은 한 필드)**, **역방향 포함 금지**, **부분포함은 허용 목록·거부어와 함께만**. `orderNumber`의 거부어는 `앞부분·구매·고유·매입`, `productId`는 `마스터·판매자·업체`, `productName`은 `코드·id·옵션명`.

- 시트명: `state.sourceMeta.sheetName`(가져온 시트명, 샘플은 `2026-09-07`) ‖ 내보내는 날짜 `YYYY-MM-DD`. 시트명 금지문자 치환·31자 제한은 `book_append_sheet`가 이미 처리.
- 파일명: `송장업로드_YYYYMMDD_HHmm.(xls|xlsx)` (전체 모드는 `주문목록_…`).
- 형식: 버튼은 **xlsx / xls 둘 다**. 기본값 = 가져온 파일의 형식(`sourceMeta.format`: xls→xls, xlsx→xlsx, csv·붙여넣기→xls). 근거: 프로그램이 `.xls`로 내보내니 `.xls`를 읽을 가능성이 가장 높지만(추정) 확인된 바 없음. 사용자에게 "수집 프로그램 업로드 창이 받는 확장자"를 한 번 물어 기본값을 설정에 저장(`rules.exportFormat`).
- `.xls` 쓰기는 `xlsx-compat.write(bookType:"xls")`가 `BiffXls.buildBytes`를 부르도록 이미 짜여 있고, **엔진만 없음**. BIFF8 최소 쓰기(BOF·CODEPAGE 1200·WINDOW1·FONT·FORMAT·XF·STYLE·BOUNDSHEET·SST·DIMENSIONS·ROW·LABELSST·NUMBER·EOF)면 충분합니다. 읽기는 BOF/BOUNDSHEET/SST/LABELSST/LABEL/RK/MULRK/NUMBER/FORMULA(캐시값)/FORMAT/XF(날짜 서식 판별)/CONTINUE 처리 + CFB 디렉터리(`Workbook`/`Book` 스트림, 미니스트림) 파싱이 필요합니다. 샘플·워크북 모두 BIFF8이라 BIFF5 이하는 지원하지 않아도 됩니다.
- CSV는 36열 내보내기에서 제외(3.4).

## 6. 정책 결정이 필요한 것

1. **`계정`·`카드정보` 열의 내보내기.** 절대 원칙은 "계정/카드 정보는 어떤 내보내기에도 포함 금지"입니다. 그러나 새 양식 26·30열은 수집 프로그램이 정의한 열이고, 워크북 실값은 `구매처(담당자)` 별칭과 카드사 이름뿐입니다(확인). 제안: (a) 두 열은 **라벨 문자열만** 저장·내보내고, 계정관리·카드관리 탭(`ops.accounts/cards`)과는 어떤 참조도 만들지 않는다. (b) 설정에 "36열 내보내기에 계정·카드 라벨 포함"(기본 ON — 왕복 보존이 목적)을 두고 끄면 두 열을 빈칸으로 낸다. (c) 아이디·비밀번호·카드번호 같은 값이 라벨 칸에 들어가지 않도록 입력 UI는 select(설정의 라벨 목록)로만 받는다. 사용자 확인 필요.
2. **가져오기 = 교체 vs 병합.** 구앱은 올릴 때마다 `state.orders`를 교체합니다. 새 양식 시트명이 날짜(`2026-09-07`)인 것으로 보아 **하루 단위 파일**일 가능성이 큽니다(추정). 그러면 월별 대시보드를 위해 `uniqueNo` 기준 **병합(upsert)** 이 맞습니다: 같은 키는 원본 열만 갱신(앱 입력 열은 앱 값 유지, 단 파일의 송장·주문여부가 더 진행됐으면 반영), 새 키는 추가, 파일에 없는 기존 행은 그대로. "교체"는 설정 또는 업로드 화면 체크박스로.
3. **판매사이트 주문번호의 두 토큰**이 각각 무엇인지(5.3).
4. 코드 모르는 택배사(우체국·경동 등)의 T코드 — 수집 프로그램 코드표를 사용자가 받아 설정에 입력.

## 7. 재업로드·복원 (keyOf)

- 현재 `keyOf = orderNumber¶productId¶option¶recipient`. 새 양식에서 재료의 안정성: `orderNumber`(고유, 확인)·`productId`(있음)·`option`(있음)·`recipient`(사용자가 시트에서 오타를 고치면 키가 바뀌어 상태 유실 — 구조적 약점).
- **제안: `keyOf(o) = uniqueNo ? "u:" + uniqueNo : legacyKey(o)`.** `주문고유번호`는 수집 프로그램 쪽 행 식별자이고(4.송장업로드리스트 설명문), 266행 중복 0, 편집 불가 열이라 가장 안정적입니다.
- 복원 순서: `states["u:"+uniqueNo]` → 없으면 `states[legacyKey]`(옛 저장분·쿠팡 발주서 호환). 저장은 새 키로만(`persist`), 옛 키 항목은 90일 정리에 맡깁니다.
- 같은 파일 재업로드 시나리오: 파일에 `주문여부=O·송장`이 채워져 돌아오면 3.2의 "파일이 더 진행됐으면 파일 우선" 규칙으로 `invoiced`가 되고, 앱에서만 입력한 `memoLog·cs*·sourcingLinks·discount`는 states에서 그대로 복원됩니다. 앱에서 송장을 입력했는데 파일은 빈칸이면 states 값 유지.
- `o.id`는 `"o"+idx+"_"+hash(주문번호+상품명+idx)`로 행 순서에 묶여 있습니다. 병합을 도입하면 `id`도 `uniqueNo` 기반(`"u"+uniqueNo`)으로 두는 편이 DOM `data-id` 안정성에 좋습니다.

## 8. 붙여넣기(TSV)·CSV·구글시트 경로

| 경로 | 흐름 | 어댑터 적용 | 주의 |
|---|---|---|---|
| xlsx 파일 | `readWorkbook → sheet_to_json(raw:false) → processOrderParsed` | `autoMap`/`buildOrders` 한 곳 | 숫자가 문자열로 옴 → `asIdString`이 `.0` 처리 |

## 부록 A. 검증에 쓴 매핑 프로토타입 (요지)

```js
// norm: 공백(U+3000 포함) 제거 + 소문자 — 구앱 그대로
function autoMap(header) {
  var map = {}, used = {}, nh = header.map(norm);
  var hits = 0;
  for (var i = 0; i < SOURCE36.length && i < header.length; i++) if (nh[i] === norm(SOURCE36[i])) hits++;
  if (hits >= 30) {                       // 0) 양식 감지 → 위치 매핑
    SOURCE36_KEYS.forEach(function (key, idx) { if (idx < header.length) map[key] = header[idx]; });
    map.__template = "source36"; return map;
  }
  FIELDS.forEach(function (f) {           // 1) 정확 일치, 헤더 소비
    for (var a = 0; a < f.aliases.length; a++) { var na = norm(f.aliases[a]);
      for (var i = 0; i < header.length; i++) if (!used[i] && nh[i] === na) { map[f.key] = header[i]; used[i] = 1; return; } }
  });
  FIELDS.forEach(function (f) {           // 2) 부분포함: 허용 필드만, 헤더⊃별칭 방향만, 거부어 제외
    if (map[f.key] || !f.partial) return;
    for (var a = 0; a < f.aliases.length; a++) { var na = norm(f.aliases[a]); if (na.length < 3) continue;
      for (var i = 0; i < header.length; i++) { if (used[i] || !nh[i]) continue;
        if (nh[i].indexOf(na) !== -1 && !(f.deny || []).some(function (d) { return nh[i].indexOf(norm(d)) !== -1; })) {
          map[f.key] = header[i]; used[i] = 1; return; } } }
  });
  return map;
}
```

실행 결과(4.2)는 이 문서 작성 시 `/tmp/…/scratchpad/automap2.js`로 확인했습니다. 앱에 넣을 때는 `SOURCE36_KEYS`(36개 필드 키 배열)와 `FIELDS`의 `partial/deny` 속성을 추가하면 됩니다.
