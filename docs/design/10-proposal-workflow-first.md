## 0. 한눈에 보기

### 0.1 결론

1. **하루 흐름은 다섯 화면이 아니라 세 화면이면 끝난다**: `주문관리`(발주) → `송장`(송장 붙이기·36열 내보내기) → `CS`. 나머지 12개 탭은 없애지 않고 **"보조" 줄로 내려** 첫 줄에서 치운다. 코드 삭제 없음, `TABS` 배열과 `render()` 디스패치만 손댄다.
2. **발주 1건당 손이 가는 횟수를 4클릭+5칸 입력 → 4클릭+2칸 입력으로 줄인다.** 방법은 세 가지뿐이다: (a) `[발주완료]` 한 번에 담당자·구매처·계정·카드를 **설정의 기본값(또는 직전 행 값)** 으로 채우고, (b) 완료 직후 포커스를 `구매금액` 칸으로 보내고 Enter로 `구매처 주문번호` → 다음 미처리 행으로 넘어가게 하며, (c) 여러 행을 골라 `일괄 입력`한다.
3. **송장 단계는 "붙여넣기 → 대조 → 내보내기"를 한 탭 안에서** 끝낸다. 기존 `운송장업로드` 탭을 `송장` 탭으로 이름만 바꾸고, 주문고유번호 기준 대조 붙여넣기와 "아직 안 올린 건만" 내보내기를 얹는다. 내보낸 행에는 `invoiceUploadedAt`을 찍어 두 번 올리는 사고를 막는다.
4. **대시보드는 카드 격자가 아니라 숫자 한 줄 + 표**로 바꾸고, 숫자마다 클릭하면 해당 화면으로 간다(남은 주문 → 주문관리 미처리 필터, CS 내 차례 → CS 오늘 할 일, 위험 → 위험 모달). "버튼 한 번으로 왔다 갔다"는 탭 수를 줄이고 숫자를 링크로 만드는 것으로 해결된다.
5. 블랙리스트·CS·36열 내보내기·복사 툴바는 **이미 구현돼 있다 [확인]**. Phase B에서는 "반복 사용 시 귀찮은 점"만 고친다: 매번 뜨는 위험 모달 → 새 일치만, 오탐 무시 버튼, 이름만 등록된 사람은 노란색(설정), CS차감 칸의 이중 입력 정리, 백업/복원.

### 1.1 흐름 (사용자 설명 + 워크북 시트 구성에서 재구성) [확인+추정]

```
아침  ① 수집 프로그램에서 .xls 내려받기 → 앱에 올리기(합치기) → 위험 모달 확인
낮    ② 미처리 행마다: 배송지 복사/자동입력 → 구매처에서 결제 → 앱에 발주 기록
```

## 2. 상단 탭 구성

### 2.1 현재 [확인: `TABS` 982–998]

`프로세스 · 대시보드 · 주문관리 · CS관리 · 블랙리스트 · 라인업 · 매입처DB · 마진계산기 · 일별매출 · 운송장업로드 · 로스관리 · 수행일지 · 계정관리 · 카드관리 · 수익분석` = 15개 + 설정 모달. `.tabs`는 `overflow-x:auto`라 폭이 좁으면 옆으로 스크롤된다.

### 2.2 제안: 두 줄, 위 줄은 하루 흐름 순서

```
┌────────────────────────────────────────────────────────────────────────────────┐
│ 대시보드   주문관리 12   송장 5   CS 4   블랙리스트 1   매입처DB      보조 ▾  설정 │
└────────────────────────────────────────────────────────────────────────────────┘
   보조 ▾ = 라인업 · 마진계산기 · 로스관리 · 수익분석 · 수행일지 · 계정·카드 · 프로세스
```

| 탭 | 처리 | 근거 |
|---|---|---|
| **대시보드** | 유지 + `일별매출`·`수익분석` 표를 여기로 흡수(§4) | 둘 다 `state.orders` 집계뿐(`dailySalesRows` 2091, `renderProfit` 2223) — 별도 탭일 이유가 없음 |
| **주문관리** | 유지. 배지 = 미처리 건수 | 하루의 80% |
| **송장** | `운송장업로드`를 개명. 붙여넣기 대조 + 36열 내보내기 (§7) | 지금은 목록+버튼 2개뿐(2112–2124) |
| **CS** | 유지. 배지 = 내 차례+조치일 도래 건수(`csBucket==="todo"`) | 현재 배지는 CS 전체 수(`renderTabs` 1004) → "지금 할 일"로 바꿈 |
| **블랙리스트** | 유지. 배지 = 위험 건수(현행) | |
| **매입처DB** | 유지(첫 줄 마지막) | 새 소스는 구매링크·구매가를 파일이 주므로 빈도는 낮아지지만, 링크 없는 신규 상품에 여전히 필요 |
| 라인업 | 보조 | 상품 기획용. 매일 아님 |
| 마진계산기 | 보조 | 독립 계산기 |
| 로스관리 | 보조 (또는 CS 종결 섹션에 합계 흡수, §6) | `renderLossPane`은 마이너스 마진+CS 필터일 뿐 |
| 수익분석 | 보조 → 대시보드에 카테고리 표 흡수 후 제거 검토 | |
| 수행일지 | 보조 | 강사 업무 |
| 계정관리·카드관리 | 보조, 한 탭 `계정·카드`로 합침(`renderSimpleOpsTable` 두 번 호출) | 비밀번호가 있는 탭이 첫 줄에 늘 노출될 이유가 없음 |
| 프로세스 | 보조. 향후 삭제 후보 | `process-strip`이 같은 정보를 상단에 이미 보여줌(895–921). 워크북 import의 `processNotes`도 9월 워크북엔 없음 |
| 설정 | 모달 유지 | |

**구현**: `TABS`에 `group:"main"|"more"` 속성만 추가. `renderTabs`가 main은 버튼, more는 `<select class="tab-more">`(또는 두 번째 줄 토글)로 그린다. `TAB_PANE`·`render()` 디스패치·모든 `pane-*` DOM은 그대로. `state.ui.tab`이 more 그룹 값이면 그 select가 선택 상태로 보이게 한다. **`init()`의 `#tabnav` 위임(`[data-tab]`)은 그대로 쓰되 select의 `change`만 추가**.

**키보드**: 입력칸에 포커스가 없을 때 `Alt+1`~`Alt+6` = 첫 줄 탭. 기존 `onSeqKey`(3318)와 같은 방식으로 `document`에 1회 바인딩, `input/select/textarea` 포커스 시 무시.

**"버튼 한 번으로 왔다 갔다"**: 탭 외에 다음 링크를 둔다(모두 `setTab` 또는 기존 `gotoOrder`/`csOpenId` 재사용).
- 대시보드 숫자 → 해당 탭(§4).
- 시트 `상태` 칸의 CS 줄(`cs-line`) → 클릭하면 `state.ui.csOpenId=o.id; setTab("cs")`.
- CS 행 `[주문으로]` → 현행 `gotoOrder`.
- 위험 배지 → 위험 모달(현행 `data-risk-list`) + 모달의 `[주문으로]`(현행).
- 상단 바 `[송장 파일]`(현행) 옆에 아무것도 더 두지 않는다(상단 버튼 4개 유지).

## 3. 주문관리 시트

### 3.1 현재 열 [확인: `SHEET_COLS` 2282–2313, 31열]

`완료 · 입력 · 위험 · 주문번호(구매처) · 담당자 · 구매처 · 계정 · 구매링크 · 구매가 · 구매금액 · 카드 · 포인트 · 순마진 · 주문일 · 주문번호 · 상품명 · 옵션 · 수량 · 결제액 · CS차감 · 수취인 · 전화 · 우편번호 · 주소 · 배송메세지 · 한줄메모 · 택배사 · 송장번호 · 상태 · 출고중지 · 반품접수` + 사용자열 + 삭제.

문제: (a) 발주 입력 칸이 원본 읽기 칸과 섞여 있어 눈이 왕복한다. (b) `구매링크` 220px가 텍스트로 차지한다. (c) 포인트·담당자·구매가·우편번호·전화는 하루에 거의 안 본다. (d) `CS차감`은 CS 장부가 있으면 `csSync`가 덮어써서 시트에서 고친 값이 사라진다(1076–1078).

### 3.2 제안: 3구역 + 열 프리셋

```
 #  │완료│입력│위험│상태│ 구매처 │ 계정 │카드│ 구매금액 │ 구매처 주문번호 │ 결제일시 │ 순마진 ║ 주문일 │ 주문번호 │ 상품명 │ 옵션 │수량│ 판매가 │ 수취인 │ 주소 │ 배송메세지 ║ 택배사 │ 송장번호 ║ 출고중지 │ 반품 │ 한줄메모 │ ✕
    ◄────── 작업(고정) ──────►◄──────────── 발주 입력(파란 칸) ────────────►◄──────────────── 원본(읽기, 회색) ─────────────────►◄─── 송장 ───►◄──── CS ────►
```

| 구역 | 열 | 규칙 |

### 3.4 딸깍 버튼

현재: `완료` 칸 체크박스(→ purchased) / `구매완료` 필(→ pending 복귀), `입력` 칸 `[입력준비]`, 툴바 `[구매완료 표시]` [확인 2454–2463, 3260]. 두 곳에서 같은 일을 한다.

제안: `완료` 칸을 **단계 버튼 하나**로.

| 상태 | 칸에 보이는 것 | 클릭하면 |
|---|---|---|
| pending | `[발주완료]` (파란 글자, 현행 `sheet-ready-btn` 스타일) | `status=purchased`, `paidAt=now`(비었을 때), `orderedYn=O`, 담당자·구매처·계정·카드가 비면 **기본값 → 없으면 직전에 발주완료한 행 값**(`state.ui.lastPurchase`), 포커스를 같은 행 `구매금액`으로 |
| purchased | `구매완료` 필(초록) | 되돌리기 확인 없이 pending(현행). 단 구매금액이 있으면 `showConfirm` |
| invoiced | `송장완료` 필 | 클릭 무시(툴팁: 송장 탭에서) |

`[구매완료 표시]`(툴바)는 같은 함수(`markPurchased(o)`)를 호출하게 통일. `data-act="done"` 분기 안에서 처리하므로 `init()` 바인딩 변경 없음.

**Enter 흐름** (`onSheetKey` 2716 확장): `구매금액`에서 Enter → 같은 행 `구매처 주문번호`(현재는 아래 행 같은 열로 이동 [확인]) → 거기서 Enter → **다음 미처리 행**의 `완료` 칸으로 포커스 + `selectSheetRow`. 설정 `자동으로 다음 행` 켜짐/꺼짐(기본 켜짐). 다른 열의 Enter는 현행(아래 행 같은 열) 유지.

### 3.5 원클릭 복사 툴바 배치

현행 위치(시트 위 sticky, 행 선택 시 표시)와 버튼 순서는 04 보고서대로 이미 구현 [확인 3224]. 손댈 것:

1. 툴바가 없을 때(행 미선택) 한 줄 높이만큼 빈 자리를 유지해 시트가 위아래로 들썩이지 않게(`min-height` 또는 안내 문구 "행 번호를 클릭하면 복사 버튼이 나옵니다").
2. `[구매완료 표시]` → `[발주완료]`로 이름 통일(§3.4).
3. `CS ▾` select는 유지. 여기서 고르면 CS 탭으로 이동하는데(`csOpen` 기본 `stay:false`) 발주 중에는 **이동하지 않고** 토스트+배지만 갱신하는 편이 흐름이 안 끊긴다 → `stay:true` + 토스트에 `[CS로 이동]` 링크. 시트의 출고중지/반품 체크는 이미 `stay:true` [확인 2684].
4. 선택 행이 `raw`에 배송메세지가 없는 쿠팡 발주서 주문이면 `[배송메시지]`가 비활성인데, 툴팁으로 이유를 보여준다(현행은 그냥 비활성).
5. **다중 선택**: `Shift+행번호 클릭`으로 범위, `Ctrl+클릭`으로 토글. 2건 이상이면 툴바가 `선택 3건 · [구매처][계정][카드] 일괄 입력 · [발주완료 3건] · [CS ▾]`로 바뀐다. `state.ui.selectedIds=[]` 추가, 단일 선택 로직은 `selectedIds.length===1`일 때 현행 그대로.

### 5.2 Phase B에서 고칠 것

1. **모달은 "새로 생긴 일치"만** [추정: 매일 합치기 업로드면 어제 본 위험 건이 매일 다시 뜸]. `state.ui.riskSeen = {uniqueNo: level}`을 두고, `finalizeOrders` 뒤 모달은 `riskSeen`에 없거나 레벨이 올라간 건만 보여준다. 배너는 계속 전체 건수.
2. **오탐 무시**: 위험 배지 클릭 → 작은 팝오버(사유 목록 + `[등록 정보]` + `[이 주문은 오탐 — 무시]`). 무시하면 `o.riskDismissed=true` → 행 색 해제, 배지는 회색 점, 집계에서 제외. `persist`의 states 스냅샷에 `riskDismissed` 추가(재업로드 후에도 유지). `computeRisk`는 판정을 그대로 두고 표시만 바꾼다(판정 로직 오염 금지).
3. **이름만 등록된 사람 = 주의(노랑)를 기본으로** [결정 필요]. 현재는 위험(빨강)이다. 워크북 블랙리스트 시트가 이름 위주라면(01 §부록B, 추정) 흔한 이름의 무고한 고객이 매번 빨간 행이 된다. 등록 항목마다 `strict`(이름만으로도 위험) 체크를 두고, 기본은 주의. `check()` 한 줄 변경: `level = b.strict ? "danger" : "warn"`. 사용자 요구("이름·주소 일치 시 빨간색")는 유지된다.
4. **연락처 일치의 한계 명시** [확인: 03 §1.2 — 워크북 전화가 전부 안심번호 형태]. 쿠팡 안심번호는 주문마다 바뀌므로 연락처 일치는 실번호가 남은 옛 기록에서만 의미가 있다. 탭 설명문에 한 줄 적는다. 판정은 그대로.
5. **등록 경로 추가**: 복사 툴바 오른쪽 끝 `⋯` 메뉴에 `[블랙리스트 등록]`(메모 모달과 같은 확인창). CS 탭 펼친 행에도 같은 버튼(반품 악성 고객을 CS 처리 중 바로 등록).
6. **주소 정밀도 안내**: 붙여넣기 모달의 안내문에 "주소는 동·호수까지 적어야 위험으로 잡힙니다. 동네까지만 적으면 주의로만 표시됩니다"를 넣는다. 규칙을 느슨하게 하지 않는다(HANDOFF §4 경고 유지).
7. 판정 함수는 순수 함수라(`blacklist.js`) node 테스트를 붙인다(§9).

### 7.1 현재 [확인]
- 송장 입력: 시트 `택배사` select + `송장번호` input. 엑셀 블록 붙여넣기(`onSheetPaste`)는 **행 순서가 같을 때만** 맞는다.
