## 1. 지금 코드에 있는 것 (전부 [확인], 줄번호는 `app.js`)

### 1.1 복사 기반 함수
- `copyText(text, label)` 206–216: `navigator.clipboard.writeText` → 실패 또는 `file://`(비보안 컨텍스트)면 `legacyCopy`(숨은 textarea + `execCommand("copy")`) 218–229. 성공 시 토스트 "…복사됨 — 붙여넣기(⌘V)". **text/plain 한 종류만** 넣을 수 있음.
- 칸 클릭 복사: `isCopyCell = key === "recipient" || key === "address"` 1998 → `td[data-copy-cell]` → `onSheetClick` 2137–2144에서 `copyText(order[key])`. 전화·우편번호 칸은 클릭 복사 대상이 **아님**(고객 번호 노출 방지 의도로 보임 — 인수인계 문서에 "칸 자체를 클릭하면 바로 복사, 복사 아이콘 방식은 싫어함" **[확인, 문서]**).
- `formatAddress(o)` 1762–1770: `copyFormat`(`{name} / {phone} / ({zip}) {address}`)을 치환. 빈 우편번호 괄호 제거. **호출처는 설정 미리보기(`updateCopyPreview` 2616)뿐** — 실제 복사 경로 없음. 즉 "전체 한 번에 복사" 기능은 설정 UI만 있고 동작이 없음.

### 1.2 자동입력 준비 `copyAutofill(o)` 2531–2549

- 주소는 **한 덩어리**(`addr`)로만 감. 기본/상세 분리, 배송메시지, 하이픈 없는 전화 형식은 없음.

### 1.3 북마클릿 `BOOKMARKLET` 2552–2562
- `navigator.clipboard.readText()` → `JSON.parse` → `__oh` 없으면 실패 alert.
- 칸 찾기 `fd(keywords)`: 모든 `input,textarea`를 돌며 `placeholder+name+id+aria-label+label+컨테이너 innerText(40자)`를 소문자로 합쳐 **키워드가 처음 걸리는 칸 하나**를 반환(랭크 없음, 첫 매치). 이름 키워드 `받는/수령/수취/성명/이름/recipient/name`, 전화 `연락처/휴대폰/휴대전화/전화/핸드폰/phone/mobile`, 우편 `우편/zip/postal`, 주소 `주소/address/addr/도로명/지번`.
- 값 주입 `sv(input, v)`: 프로토타입 setter로 value 설정 후 `input/change/blur` 이벤트 발생(React/Vue 폼 대응).
- 한계: 주문자(구매자) 칸을 먼저 만나면 거기에 넣음, 3분할 전화 미지원, 우편번호 검색 팝업형 사이트에서 readonly 주소칸은 건너뜀(`readOnly` 제외) → 결과적으로 "주소 못 찾음". 설정 화면에도 "네이버·옥션에선 제대로 안 될 수 있음, 구형" 이라고 적혀 있음(index.html 715).

**결론: 한 주문에서 손으로 옮길 수 있는 조각은 최대 7개**입니다 — 이름 / 전화(가운데) / 전화(끝) / 우편번호 / 기본주소(검색어) / 상세주소 / 배송메시지. 그리고 어떤 사이트에서도 **우편번호·기본주소·상세주소를 한꺼번에 붙일 수 있는 칸은 없거나 드뭅니다**. 현재 `[입력준비]`의 `addr` 한 덩어리가 사람 손 폴백에서 쓸모없는 이유가 이것입니다.

## 3. 한 줄 복사 툴바 설계

### 3.1 자리와 모양
- **어디에**: 주문관리 시트에서 **행을 선택**(행 앞쪽 클릭 또는 칸 포커스)하면 시트 상단 도구줄 자리에 **한 줄** 툴바가 나타남(sticky, 스크롤해도 보임). CS 탭에서도 같은 툴바가 펼친 행 안에 뜸(02 문서 §5-2의 8번과 정합).
- **왜 hover 아이콘이 아닌가**: 사용자가 "복사 아이콘이 떠다니는 방식"을 명시적으로 싫어함(§1.1). 툴바는 항상 같은 자리에 같은 순서로 있어야 눈이 헤매지 않음. 기존 **칸 클릭 복사(수취인·주소)는 그대로 유지**.
- **모양(애플식)**: 얇은 1줄, 버튼은 `mini` 크기, 볼드 없음. 왼쪽에 `이름 · 구매처` 같은 짧은 문맥, 이어서 버튼 7개, 오른쪽 끝에 `순차` 토글과 `입력준비`(JSON).

```
[홍길동 · 11번가]  [이름] [전화 · 내번호] [우편번호] [기본주소] [상세주소] [배송메시지] [전체]     순차 ○   [입력준비 ↗]
```

### 3.2 버튼별 정확한 동작

| 버튼 | 클립보드에 들어가는 것 | 비활성/차단 조건 | 토스트 |
|---|---|---|---|
| 이름 | `수령자명` 원문(trim) | 비어 있으면 비활성 | "이름 복사됨" |

| 배송메시지 | `배송메세지` 원문(줄바꿈→공백, 최대 100자 [추정: 사이트 제한]) | 비면 비활성 | "배송메시지 복사됨" |

세부 규칙
- 모든 버튼은 `copyText()` 하나를 통해 나가며, **복사된 조각 이름을 `state.ui.lastCopied = {orderId, piece, at}`에 기록**(순차 모드와 되돌리기가 이걸 씀).
- 툴바에는 **고객 전화 버튼이 없습니다.** CS 탭의 "회수용 복사(고객 번호)"만 예외이며 별도 함수(`copyCustomerPhone`)와 빨간 라벨을 씁니다(02 문서 §5-2 8번, 이 문서 §6).
- 전화 칸의 3분할 대응: `▾`의 "가운데 4자리 / 끝 4자리"는 `phoneForms(myPhone).parts[1] / [2]`. 첫 칸은 거의 select라 붙일 필요 없음. 국번이 010이 아닌 `050x`(안심번호) 등도 `parts`가 `[국번, 가운데, 끝]`으로 나뉘도록 정규식은 `^(0\d{1,3})(\d{3,4})(\d{4})$`.

### 3.3 주소 자동 분리 규칙 `splitAddress(raw)` — 단일 기준

앱 안에서 기본/상세 분리는 **이 함수 하나**만 씁니다. 확장·북마클릿은 페이로드에 이미 분리된 `base/detail`을 받으므로 자체 분리를 하지 않게 고칩니다(현재 확장은 자체 규칙을 가진 것으로 보임 [추정, 문서 §1.4]).

반환값: `{ base, detail, ref, full, zipHint, method: 'road'|'jibun'|'guess'|'none', confidence: 'high'|'mid'|'low' }`

```
0. 정규화
   - 전각 괄호/공백 → 반각, 줄바꿈·탭 → 공백, 연속 공백 → 1개, 양끝 trim
   - "( 동명, 건물명 )" 처럼 괄호 안쪽 공백 제거 → "(동명, 건물명)"
1. 참고항목 떼기
   - 문자열 **맨 끝**이 ")"로 끝나고 짝이 맞는 마지막 "(…)"를 ref로 분리 (워크북 130/131건이 이 자리)
   - 중간에 있는 괄호는 건드리지 않음(상세주소의 일부로 봄)
2. 도로명 앵커 (method='road', confidence='high')
   ROAD = /^(.*?[가-힣A-Za-z0-9·.]+(?:대로|로|길)(?:\s?\d+(?:번|안|가)*길)?)\s*(\d+(?:-\d+)?)(?![\d-])/
   - 그룹1 = 도로명까지, 그룹2 = 건물번호. base = 그룹1 + " " + 그룹2
   - 나머지(뒤) = detail 후보. 앞머리의 "," "·" 공백 제거
   - 예: "OO시 OO구 OO로 12, 101동 1001호" → base "OO시 OO구 OO로 12" / detail "101동 1001호"
   - 예: "OO로12번길 5 2층" → base "OO로12번길 5" / detail "2층"
3. 지번 앵커 (2가 실패했을 때만. method='jibun', confidence='mid')
   JIBUN = /^(.*?[가-힣]+(?:읍|면|동|리|가)\s*(?:산\s*)?\d+(?:-\d+)?(?:번지)?)(?![\d-])/
   - "[가-힣]+동" 이라 "101동"(숫자+동)은 걸리지 않음. 그래도 2를 먼저 시도하는 이유: 도로명 주소 뒤의 "행복동 3호" 같은 상세를 지번으로 오인하지 않기 위해
   - 예: "OO군 OO면 OO리 123-4 OO빌라 B동 201호" → base "…OO리 123-4" / detail "OO빌라 B동 201호"
4. 추측 (2·3 모두 실패. method='guess', confidence='low')
   DETAIL_START = /(\d+동\s*\d+호|\d+호|\d+층|[가-힣A-Za-z0-9]+(?:아파트|APT|빌라|오피스텔|타워|빌딩)\b)/
   - 첫 매치 위치 앞 = base, 뒤 = detail. 툴바에 노란 점 표시 + 툴팁 "분리 확신 낮음 — 확인하세요"
5. 실패 (method='none')
   - base = full, detail = "", 툴바 [상세주소] 비활성, [기본주소] 클릭 시 전체가 복사되고 토스트로 알림
6. 검증(2~4 공통)
   - detail 안에 다시 ROAD가 매치되면(도로명이 두 번) → method='none'으로 강등
   - base 길이 < 6 또는 detail 길이 > 60 → confidence='low'
   - detail이 비고 ref만 있으면 detail은 빈 값 그대로 (단독주택·상가 1층 등 정상 케이스)
7. ref 정책 (설정 `addrRefPolicy`)
   - 'drop'(기본): 팝업형 사이트는 결과 선택 시 "(동, 건물명)"을 스스로 붙이므로 상세에 넣지 않음
   - 'append': 통합 한 칸형만 쓰는 사용자용. detail 끝에 " (ref)" 붙임
   - [전체]/[입력준비]의 addrFull 에는 항상 원문(ref 포함)을 넣음
```

**왜 이렇게까지 나누나**: 다음/카카오 우편번호 팝업은 "도로명+건물번호" 또는 "지번" 또는 "건물명"으로 검색할 때 결과가 나오고, `101동 1001호`까지 붙은 문자열을 넣으면 검색 결과가 0건인 경우가 많습니다 **[추정: 일반 사용 경험]**. 즉 사람이 손으로 붙이는 상황에서 "기본주소 = 팝업 검색어" 품질이 곧 속도입니다.

### 3.4 우편번호 규칙
- 가져오기 단계(`buildOrders`)에서 `zipcode = String(v).replace(/\.0$/,'')`; `/^\d{4}$/`면 `padStart(5,'0')`; `/^\d{5}$/`면 그대로; `/^\d{3}-?\d{3}$/`면 구우편번호로 표시(복사는 원문). 이 보정은 **송장 내보내기(36열 그대로)에도 적용된 값이 나가야** 수집 프로그램에 4자리가 되돌아가지 않음.
- 우편번호 버튼은 팝업형 사이트에선 쓸 일이 거의 없지만(팝업이 채움), 통합형과 "우편번호로 검색" 팝업에서 쓰이므로 유지.

### 3.5 전화 형식기 `phoneForms(myPhone)`
```
digits = myPhone.replace(/\D/g,'')
parts  = digits.match(/^(0\d{1,3})(\d{3,4})(\d{4})$/)  → ['010','1234','5678'] (실패 시 [digits])
hyphen = parts.join('-')      // 010-1234-5678
plain  = digits               // 01012345678
```
- 설정 `myPhone` 저장 시 `digits.length`가 9~11이 아니면 저장 거부 + 안내(오타로 엉뚱한 번호가 구매처에 들어가는 사고 방지).
- 확장은 칸 속성(`maxlength≤11`/`inputmode=numeric`/`pattern`)으로 `plain`을 고르는 현행 규칙 유지, 3분할 칸(`name`에 `2/3`, `mid/last`, 또는 같은 컨테이너에 전화 input 2개)이면 `parts[1]/parts[2]`.

### 3.6 [전체] 텍스트 형식 — `copyFormat`을 살리되 기계도 읽게
- 기본값을 **줄 단위 라벨 형식**으로 바꿉니다(v2의 `shippingText`에서 형식만 차용):
  ```
  받는분: {name}
  연락처: {phone}
  우편번호: {zip}
  주소: {base}
  상세: {detail}
  요청사항: {memo}
  ```
- 토큰: 기존 `{name} {phone} {zip} {address}` + 신규 `{base} {detail} {ref} {memo}`. `{address}`는 원문 전체. 빈 값 줄은 통째로 제거(`formatAddress`의 빈 괄호 제거 로직을 "빈 줄 제거"로 확장).
- 이 형식은 북마클릿이 `readText()`만으로도 정규식(`^받는분:\s*(.+)$` …)으로 파싱할 수 있어 **JSON 없이도 폴백 자동입력이 가능**합니다(§5.3).
- 한 줄 형식(`{name} / {phone} / ({zip}) {address}`)을 원하는 사용자는 설정에서 바꿀 수 있음(기존 UI 그대로).

### 3.7 `내 번호` 미설정 차단 — 불변식으로 고정
- **INV-1** 툴바 [전화]·[전체]·[입력준비], 페이로드 v2의 `phone`, 확장·북마클릿이 채우는 전화 칸 — 이 모든 경로의 전화 값은 `state.rules.myPhone` **하나의 출처**에서만 나온다. 주문 객체의 `phone/mobile`을 읽는 코드는 시트 표시, CS 회수용 복사, 36열 내보내기 세 곳뿐이다.
- **INV-2** `myPhone`이 비어 있으면 위 경로는 **모두 실패**하고(복사 안 됨) 설정 창의 내 번호 칸으로 포커스가 간다. 고객 번호로 대체하는 폴백은 어떤 이유로도 두지 않는다(v2 방식 금지).
- **INV-3** 툴바의 [이름]·[우편번호]·[기본주소]·[상세주소]·[배송메시지]는 `myPhone`과 무관하게 동작한다(전화가 아니므로 차단 불필요). 단 [전체]는 전화 줄을 포함하므로 차단.
- 코드에서는 `getAutofillPhone()` 한 함수만 `myPhone`을 돌려주고, 비어 있으면 `null`을 돌려주며 호출측은 `null`이면 즉시 중단 — 문자열 `""`을 돌려주지 않게 하여 "빈 전화가 조용히 붙는" 회귀를 막는다.

## 4. "순차 복사" 모드 — 타당성 검토

**아이디어**: 툴바의 `순차` 토글을 켜면 첫 조각이 강조되고, 복사할 때마다 자동으로 다음 조각이 강조된다. 사용자는 앱 창에서 **같은 자리(강조된 버튼)만 반복 클릭**하고 사이트에 붙인다.

### 4.1 타당한 점
- 클립보드는 한 슬롯이므로 사람 손 폴백은 어차피 **한 번에 한 조각**입니다. 순차 모드는 "어느 버튼을 누를 차례인지"를 기억하는 부담을 없앱니다.
- 앱 창을 결제창 옆에 **좁게 나란히** 두고 쓰면(툴바가 한 줄이라 좁은 폭에서도 보임) 창 전환이 아니라 클릭 두 번(앱 → 사이트)만 남습니다.
- 사이트별 순서 프리셋을 `구매처` 열 값으로 자동 고를 수 있습니다(구매처가 행에 이미 있음).

### 4.2 한계 (설계에 반영)
- **앱은 사용자가 붙여넣었는지 알 수 없습니다.** 다른 창의 붙여넣기 이벤트는 앱에 오지 않습니다. 그래서 "다음으로 넘어가는 시점" = **복사한 시점**이어야 하고, 잘못 붙였을 때 되돌릴 수 있어야 합니다(이전 버튼을 그냥 클릭하면 그 조각이 다시 복사되고 그 자리부터 다시 진행).
- **앱이 포커스를 되찾을 때 자동으로 다음 조각을 클립보드에 넣는 "완전 자동 순차"는 만들지 않습니다.** 클립보드 쓰기는 문서가 포커스를 가진 상태에서만 되고, Safari 등은 사용자 제스처를 요구합니다 **[추정: 브라우저 정책]**. 게다가 사용자가 앱을 힐끗 본 것만으로 클립보드가 바뀌면 사고가 납니다. 항상 **클릭(또는 키)** 이 있어야 넘어갑니다.
- 팝업형(a)에서는 "기본주소 붙임 → 팝업에서 결과 선택 → 상세주소 붙임" 사이에 사이트 쪽 조작이 끼어 있어 순차 모드가 끊깁니다. 이건 문제라기보다 자연스러운 흐름이고, 강조된 다음 버튼이 `[상세주소]`로 남아 있으면 됩니다.
- 조각 수가 6~7개이고 창을 오가는 비용이 있어, **확장이 되는 사이트에서는 확장이 항상 더 빠릅니다.** 순차 모드는 "확장이 안 뜨는 사이트(iframe 결제폼, 폼 구조 변경, 확장 미설치 브라우저)"의 1순위 폴백으로 자리매김합니다.

### 4.3 스펙
- 상태: `state.ui.seq = { on, orderId, preset, idx }`. 행을 바꾸면 `idx=0`으로 리셋. ESC 또는 토글로 해제.
- 프리셋(설정에서 편집 가능, 기본값):
  - **P1 팝업형**(기본: 11번가·지마켓·옥션·롯데온·롯데홈쇼핑·SSG·네이버): 이름 → 전화 → 기본주소 → 상세주소 → 배송메시지
  - **P2 통합형**: 이름 → 전화 → 우편번호 → 전체주소(=`{address}` 원문) → 배송메시지
  - **P3 3분할 전화형**: 이름 → 전화(가운데) → 전화(끝) → 기본주소 → 상세주소 → 배송메시지
  - 구매처 → 프리셋 매핑은 설정 표(`구매처명: P1|P2|P3`). 매핑이 없으면 P1.
- 표시: 강조 버튼에 얇은 파란 테두리 + 진행 `3/5`. 복사 완료 조각은 체크 표시(볼드 없이 색만).
- 키보드(앱에 포커스가 있을 때만): `Enter`/`Space` = 강조된 조각 복사 후 다음, `←`/`→` = 이동, `Esc` = 해제. 시트 입력칸에 포커스가 있으면 이 단축키는 비활성(기존 Enter=아래 행 이동과 충돌 방지, `onSheetKey` 2190).
- 마지막 조각을 복사하면 툴바에 `[구매완료로 표시]`가 나타나 "딸깍 한 번으로 주문처리"(완료 체크 = `status='purchased'`)로 이어짐. 자동으로 완료 처리하지는 않음(사용자가 결제 전 확인해야 함).

**판정: 만들 가치 있음. 단 "폴백의 왕"으로, 확장 대체가 아님.** 구현 난이도는 낮습니다(툴바 위에 상태 하나와 강조 표시).

## 5. 북마클릿 · 확장 연동 스펙

### 5.1 클립보드 페이로드 v2 (JSON)

```json
{
  "__oh": 2,
  "name":     "수령자명",
  "phone":    "설정 myPhone — 하이픈 형식(010-1234-5678)",
  "phoneDigits": "01012345678",
  "phoneParts":  ["010","1234","5678"],
  "zip":      "배송지우편번호 (5자리, 0 채움)",
  "base":     "splitAddress().base",
  "detail":   "splitAddress().detail",
  "ref":      "splitAddress().ref (동명, 건물명 — 있으면)",
  "addr":     "배송지주소 원문 전체 (v1 호환 키)",
  "memo":     "배송메세지 (없으면 빈 문자열)",
  "split":    "road | jibun | guess | none",
  "ts":       1757145600000
}
```

| 36열 소스 필드 | 주문 객체 | 페이로드 키 | 가공 |
|---|---|---|---|
| 수령자명 | `recipient` | `name` | trim |
| (없음 — 설정) | `rules.myPhone` | `phone/phoneDigits/phoneParts` | §3.5 |
| 수령자휴대폰번호 / 수령자전화번호 | `phone` | **(넣지 않음)** | INV-1 |
| 배송지우편번호 | `zipcode` | `zip` | §3.4 |
| 배송지주소 | `address` | `base/detail/ref/addr/split` | §3.3 |
| 배송메세지 | `deliveryMemo`(신규 필드) | `memo` | 줄바꿈→공백 |
| 그 외 33열 | — | **절대 포함 금지** | 주문번호·상품명·금액·구매자명·계정·카드·주문고유번호 모두 제외 |

- `__oh: 2`로 올리고, 확장/북마클릿은 `__oh === true || __oh >= 1`을 모두 받아들이되 v1이면 `base=addr, detail=""`로 취급(구버전 앱과의 호환).
- `ts`: 확장은 **30분 이상 지난 페이로드는 거부**(예전 주문의 배송지를 다른 사이트에 붙이는 사고 방지)하고 "앱에서 [입력준비]를 다시 누르세요"라고 안내. 30분은 초기값이며 확장 옵션에서 조정.
- 확장이 채우기를 마치면 **클립보드를 빈 문자열로 덮어쓰는 옵션**(기본 켜짐)을 권장 — 고객 배송지가 클립보드에 남아 다른 곳에 붙는 것을 막음. 단 사람 손 폴백 중에는 꺼야 하므로 §5.4의 패널에서 끌 수 있게.

### 5.2 사람용 텍스트와 JSON을 한 번에 넣는 방법
- 클립보드에는 슬롯이 하나지만 **MIME 타입은 여러 개**를 넣을 수 있습니다. `[전체]`와 `[입력준비]`를 하나로 합치려면 `navigator.clipboard.write([new ClipboardItem({ "text/plain": 사람용텍스트, "web application/x-orderhelper+json": JSON })])`를 씁니다. 크롬 104+는 `web ` 접두사의 사용자 정의 형식을 지원하고, 확장은 `navigator.clipboard.read()`로 그 형식을 먼저 찾고 없으면 `text/plain`을 §3.6 규칙으로 파싱합니다 **[추정: 브라우저 지원 범위, 실기기 검증 필요]**.
- `file://`(비보안 컨텍스트)나 Safari에서는 `ClipboardItem`이 안 될 수 있으므로 **폴백은 text/plain의 라벨 형식 텍스트 하나**이고, 확장/북마클릿은 그 텍스트도 읽을 수 있게 만듭니다. 결과적으로 "[전체] 한 번 누르면 사람도 붙이고 확장도 읽는" 상태가 됩니다.
- 이 통합이 불안하면 1단계에서는 버튼 두 개(`[전체]`=텍스트, `[입력준비]`=JSON)로 시작해도 됩니다. 툴바 설계는 두 경우 모두 수용합니다.

### 5.3 북마클릿 v2 (확장을 못 쓰는 브라우저용)
- `readText()` → JSON이면 v2 파싱, 아니면 라벨 텍스트 파싱, 둘 다 아니면 붙여넣기 박스(`prompt`)로 받기.
- 칸 찾기를 "첫 매치"에서 **랭크 방식**으로 바꿈(확장 규칙을 그대로 축약): 칸 속성 점수 3, 직접 label 2, 컨테이너 텍스트 1, `주문자/구매자/결제자/buyer/orderer`가 보이면 −5, `email/password/search/coupon/memo/pin`은 제외.
- readonly인 우편번호·기본주소 칸은 채우지 않고, 대신 **작은 떠 있는 패널**을 페이지 오른쪽 아래에 그려 `[기본주소] [상세주소] [배송메시지] [전화 숫자만]` 조각 복사 버튼을 제공(북마클릿은 페이지 컨텍스트에서 실행되므로 사용자 클릭으로 클립보드 쓰기가 가능). 즉 자동으로 안 되는 칸은 **같은 페이지 안에서** 조각을 복사해 붙일 수 있고, 앱으로 돌아갈 필요가 없음.
- `alert` 2곳은 유지(외부 페이지에서 앱 toast를 못 씀 — GPT_HANDOFF §"유지" 항목).

### 5.4 확장 v1.5 요구사항(문서 기반 차분)
1. 페이로드 v2 읽기, v1 호환. `base/detail`은 앱 값을 그대로 쓰고 자체 분리 제거(단일 기준 원칙).
2. 채우기 순서: 이름 → 전화(칸 속성으로 `phone/phoneDigits/phoneParts` 중 선택) → 주소검색 버튼 클릭 → **팝업 검색어는 자동 입력하지 않음**(다음우편번호 팝업은 다른 도메인의 iframe/창이라 접근 불가 [추정]) → 사람이 검색·선택 → "주소 적용 신호" 감지(현행) → `detail` 입력 → 요청사항 select 매핑 → 없으면 직접입력에 `memo`.
3. 요청사항 select 매핑 사전(옵션 텍스트 부분일치): `문앞|문 앞|부재 시 문` ← memo에 `문앞/문 앞/문에/앞에`; `경비실` ← `경비`; `택배함|무인` ← `택배함/보관함`; `직접 입력|직접입력|기타` ← 나머지 및 **숫자 포함 메시지 전부**. 매핑 실패 시 select는 건드리지 않고 패널에 "요청사항은 직접 고르세요" 표시.
4. **패널(확장 UI)에 조각 복사 버튼 7개를 항상 표시** — 자동입력이 일부 실패해도 사용자는 그 패널에서 조각을 복사해 붙임. 못 채운 칸은 페이지에서 얇은 주황 테두리로 강조하고 패널의 해당 버튼도 같은 색. 이것이 "사이트별로 자동입력이 안 되는 경우 사람이 하나씩 붙이는 폴백이 자연스럽게 이어지는 UX"의 핵심입니다: **앱 → 사이트로 한 번만 건너가면 끝**.
5. 저장 배송지가 미리 채워진 경우(옥션 확인) 덮어쓰기 유지. `기본배송지로 저장`류 체크박스는 **건드리지 않되** 체크돼 있으면 패널에 경고 한 줄("고객 주소가 계정에 저장됩니다 — 체크 해제 권장").
6. `all_frames:false` 유지. iframe 결제폼이면 버튼이 안 뜨는 것이 정상이며, 앱 툴바(순차 모드)가 폴백.
7. 완료 후 클립보드 비우기 옵션(§5.1). 30분 만료.
8. 확장 코드 갱신 시 `chrome://extensions ↻` 안내 문구를 설정 화면에 유지(index.html 711).

### 5.5 폴백 사다리 (사용자가 겪는 순서)
```
확장 버튼이 보인다 → [🚀 자동입력] → 다 채워짐 → 확인 → 결제
                                    ↘ 일부 실패 → 확장 패널의 조각 버튼으로 남은 칸만 붙임
확장 버튼이 없다(iframe·미설치) → 북마클릿 → 위와 동일
북마클릿도 없다 → 앱 툴바 순차 모드로 조각 6개 → 결제
어느 경우든 전화는 내 번호, 결제는 사람이
```
